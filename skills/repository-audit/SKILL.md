# Repository audit
## Use when
A baseline, inconsistency, reuse quality, or cleanup need must be understood.
## Do not use when
The card authorizes implementation rather than read-only assessment.
## Required context
Repository, revision, audit questions, and relevant policies.
## Procedure
Verify revision/status; inventory scope; compare claims with files and checks; classify findings.
## Constraints
Remain read-only and avoid unrequested external actions.
## Expected output
Prioritized findings, gaps, and smallest improvement slice.
## Evidence requirements
Reference concrete paths, outputs, and limitations.
## Stop conditions
Stop on unknown dirty state or an unverifiable baseline.
## Handoff
Return an audit report for operator review.
