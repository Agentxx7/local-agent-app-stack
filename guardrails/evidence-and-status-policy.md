# Evidence and status policy

- Rule: Distinguish implemented, tested, manually verified, accepted, committed, pushed, and released.
- Purpose: Prevent stronger status claims than the evidence supports.
- Applies when: Reporting progress, readiness, completion, or release state.
- Prohibited behaviour: Treating green tests or local code as automatic approval or publication.
- Required evidence: Revision identity, named checks, manual evidence, Git state, and operator decision.
- Enforcement type: OPERATOR DECISION.
- Operator override: The operator defines acceptable evidence but may not rewrite historical facts.
- Remaining limitations: Evidence relevance and sufficiency remain contextual judgments.
